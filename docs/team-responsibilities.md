# ChronosMatch — Team Responsibilities

## 1. Team Overview

**Project:** ChronosMatch — Zero-Copy High-Frequency Trading Engine  
**Organization:** Infotact Solutions  
**Team Size:** 3 Active Members  
**Team Lead:** Parth  
**Project Period:** 10 October 2026 – 10 November 2026

The team will collaborate to design, implement, test, document, and demonstrate the ChronosMatch trading engine prototype. Responsibilities are divided to ensure clear ownership while encouraging collaboration and shared understanding of the complete system.

## 2. Member 1 — Parth (Team Lead)

**Primary Responsibility:** Architecture, Core Engine, and Integration

Tasks:
- Define the initial project structure and technical approach.
- Coordinate project planning and distribute development tasks.
- Design and implement core order-book and matching-engine components.
- Establish GitHub branching and contribution practices.
- Review team contributions and coordinate integration.
- Monitor progress, identify blockers, and communicate with the mentor.
- Maintain project documentation and track deliverables.
- Coordinate final testing, reporting, and demonstration.

Expected Deliverables:
- Project architecture and implementation plan.
- Core matching-engine components.
- Reviewed and integrated contributions.
- Updated project documentation and progress records.

## 3. Member 2 — Backend and API Development

**Primary Responsibility:** API Layer, Validation, and Persistence

Tasks:
- Design API endpoints using FastAPI.
- Implement request and response validation.
- Integrate API requests with the matching engine.
- Implement order and trade data persistence where required.
- Handle expected API errors and invalid requests.
- Write tests for API endpoints and persistence.
- Document API usage and example requests.

Expected Deliverables:
- API endpoints and schemas.
- Persistence integration, where implemented.
- API tests and usage documentation.

## 4. Member 3 — Testing and Performance

**Primary Responsibility:** Test Coverage, Benchmarking, and Demonstration Support

Tasks:
- Develop unit tests for order matching and order-book operations.
- Test partial fills, cancellations, invalid orders, and edge cases.
- Build repeatable performance benchmarks.
- Measure latency and throughput under documented conditions.
- Help identify bottlenecks using profiling tools.
- Evaluate optimization results against a baseline.
- Support dashboard development and final demonstration, if included.
- Document test results and known limitations.

Expected Deliverables:
- Automated test cases.
- Benchmark scripts and recorded results.
- Profiling observations and optimization evidence.
- Test documentation and demonstration support.

## 5. Shared Responsibilities

All team members are responsible for:

- Making meaningful contributions to the project.
- Working on their assigned Git branches.
- Writing readable, maintainable, and tested code.
- Updating documentation when their work changes system behavior.
- Communicating progress and blockers promptly.
- Reviewing the overall architecture and understanding key components.
- Participating in integration, testing, and project demonstrations.
- Following the internship program's repository and review requirements.

## 6. GitHub Workflow

1. Each member works on their designated branch.
2. Members commit meaningful, related changes with descriptive messages.
3. Members push their work to the remote repository.
4. The team lead reviews contributions before integration.
5. Approved changes are merged into the main branch according to the team's workflow.
6. The team verifies integrated changes through tests.
7. The team avoids empty commits, duplicate work, and commits made only to increase activity counts.

## 7. Communication and Progress Tracking

Each member should provide regular updates covering:

- Work completed.
- Files or components changed.
- Relevant commits, pull requests, or test evidence.
- Current blockers.
- Planned next steps.

Team members should raise blockers early and collaborate to resolve integration issues.

## 8. Responsibility Updates

This document represents the initial proposed allocation of responsibilities. Tasks may be adjusted based on progress, technical requirements, mentor feedback, and the actual contributions of each member.

Each member must accurately report their own work and retain evidence of their contributions.
